# تسليم تجربة بوابة الإدارة — NatiqAAC

التاريخ: 2026-11-10. هذه ميزة تنفيذية على فرع مستقل يعتمد على Authentication V2؛ ليست إعادة تصميم لنظام المصادقة أو تغييرًا لقرارات المنتج المتعلقة بالجلسات والخصوصية.

## A. ملخص التنفيذ

أصبحت النظرة العامة ومراجعة الأخصائيين مساحة واحدة، بتنقل واضح ومحتوى عملي: عدد الطلبات المعلّقة من قاعدة البيانات، رابط مراجعة مباشر، وبطاقة حساب مبسطة. أُعيد تصميم قائمة الطلبات وتفاصيلها وتنزيل المستند وتأكيد القرارات، مع حالات التحميل والفشل والفراغ وإعادة المحاولة.

لم تُضف أقسام وهمية أو إحصاءات أو صور أطفال أو واجهات CRUD بلا API. لم تتغير مخططات Prisma أو migrations أو JWT أو Redis أو قواعد الموافقة. لا توجد تبعية جديدة.

## B. المعمارية

الغلاف `AdminLayout` يجمع sidebar/header/main/footer عبر Routes وOutlet الموجودين في React Router. يبقى SessionProvider الحالي مصدر الجلسة، وتظل حماية Admin على الخادم. يقرأ الغلاف إسقاط الحساب من `/admin/overview` ويمرره عبر outlet context. `AdminPage` يملك ملخص المعلّق، و`AdminApplicationsPage` يملك تجربة المراجعة، و`AdminIcons` عائلة SVG موحدة.

نُقلت واجهة المراجعة من ملف صفحات الحسابات إلى feature الإدارة، مع إبقاء export متوافق من الموقع السابق. CSS الإدارة محصور تحت أصنافها، والقيم المشتركة تمتد من ألوان المنتج الحالية. التفاصيل: [دليل المعمارية والتشغيل](admin-frontend-experience.md).

## D. التصميم البصري

حوفظ على teal `#176b68` وألوان النص الأصلية. أضيفت خلفية هادئة، sidebar داكن `#173f3d`، أسطح بيضاء، حدود خفيفة وظل محدود. الألوان الدلالية للمراجعة/القبول/الرفض يصاحبها نص. الخط من مجموعة النظام الموجودة، دون خط خارجي أو bitmap. تتدرج العناوين والمسافات حسب العرض؛ الأرقام ذات عرض ثابت، والعداد يحجز مساحة أثناء التحميل.

الأيقونات SVG بحجم وضربات موحدة. لا رسوم بيانية ولا أرقام تجريبية داخل منطق الإنتاج. الصور في هذا التقرير التُقطت من React الحقيقي في المتصفح **بردود API اصطناعية معترضة**؛ الرقم الظاهر فيها fixture للاختبار وليس إحصاءً حيًا للمشروع.

## E. القائمة الجانبية

وجهتان تعملان فقط: النظرة العامة وطلبات الأخصائيين. NavLink يحدد صفحة واحدة، وتعمل العلامة على الجانب المنطقي في RTL/LTR. أزيل النص التحفيزي غير العملي. على الهاتف/التابلت حتى 900px تتحول إلى disclosure داخل التدفق، لا يغطي المحتوى ولا يحبس التركيز؛ له حالة expanded وEscape وإعادة تركيز للزر. لا أقسام إدارة مستخدمين أو محتوى غير منفذة.

## F. الرأس

مسار الصفحة الحالي يظهر في الرأس. زر الخروج يحمل أيقونة واضحة ويبقى أخف من إجراء المراجعة الأساسي. اللغة في سطح صغير واحد، مع اختيار حالي واضح، دون الإطار المزدوج. بقيت دلالة أزرار اللغة ووسيلة حفظ اللغة كما هما.

## G. بطاقة الحساب

تستخدم الحساب الذي يتحقق منه endpoint الإدارة: وصف الحساب الحالي، «مسؤول المنصة»، ثم البريد. أزيل الدور المكرر. لا UUID أو JWT ظاهر، ولا شارة «بريد موثّق» لأن عقد `/admin/overview` لا يكشف هذه المعلومة. لا حالة حساب مختلقة.

## H. النظرة العامة والعدد الحقيقي

أضيف `GET /admin/specialist-applications/summary` على **نفس controller المحمي** بـJwtAuthGuard وRolesGuard وADMIN. ينفذ `COUNT` عبر Prisma لحالة `PENDING_REVIEW` فقط ويعيد `{pendingCount:number}`. السبب أن قائمة الطلبات الحالية مقيدة بـ100 ولا تصلح لحساب الإجمالي.

لا تعديل لعقد قديم أو schema. اختبارات HTTP رفضت Parent وSpecialist وAdmin الموقوف. اختبار PostgreSQL معزول أنشأ fixtures لـ105 حالات معلّقة وثلاث حالات أخرى، وأثبت أن الملخص يشمل المعلّق خارج سقف القائمة ويستبعد غير المعلّق. جميع fixtures تخص الاختبار وتُحذف ضمن تنظيفه المحدد.

العدد له تحميل وصفر وفشل وإعادة محاولة. الفشل لا يتحول إلى صفر. رابط «مراجعة طلبات الأخصائيين» يفتح الصفحة مع اختيار الحالة المعلّقة؛ رابط ثانٍ يفتح جميع الحالات. لا إحصاءات مستخدمين/أطفال/ذكاء اصطناعي.

## I. مراجعة الأخصائيين

القائمة تدعم بحثًا في الاسم والبريد والتخصص وتصفية الحالة **ضمن السجلات المعروضة فقط**. التنبيه يوضح حد 100 وعدم وجود بحث عالمي أو pagination؛ لا ادعاء بتغطية السجل الكامل. قد تبقى طلبات خارج أول 100 غير متاحة بهذه القائمة، وهو قيد API قائم يحتاج تحسينًا مستقلاً.

تظهر التفاصيل المتاحة: الاسم، البريد، التخصص، المؤهل، الملخص الاختياري، تاريخ الإرسال، الحالة، وجود PDF، وسجل القرار المتاح. المستند يُنزّل عبر الباك المصرح، دون رابط Supabase عام أو سر في المتصفح، وباسم PDF مناسب، مع معالجة الغياب والفشل.

الموافقة والرفض يحتاجان تأكيدًا يذكر صاحب الطلب. سبب الرفض يطابق حد 10–1000 حرف بعد trim. قفل طلبات يمنع الإرسال المزدوج، والأزرار تتعطل أثناء العمل. بعد النجاح تُقرأ القائمة من الخادم مجددًا، ويعود التركيز لإجراء الطلب أو عنوان الصفحة عند غيابه. الفشل يتيح تحديث التفاصيل بدل عرض نجاح وهمي. لم تتغير قواعد المراجعة أو الحذف/الاستبدال أو الاحتفاظ بالمستندات.

## J. الجلسة وتحديث الصفحة

فُحص السبب: JWT في ref خاص داخل SessionProvider، ولا توجد آلية refresh-session معتمدة. فقد الجلسة عند refresh مقصود ومطبق. لم يُضف localStorage/sessionStorage للرمز أو cookie أو refresh token، ولم يتغير CORS/CSRF أو إبطال JWT.

أزيل التحذير التقني من محتوى Admin؛ إرشاد الجلسة الموجود في تسجيل الدخول بقي هناك، ورسائل الانتهاء والخروج الحالية محفوظة. الجلسات المستمرة تحتاج قرارًا وتصميمًا منفصلين إذا أُريدت مستقبلًا.

## K. اللغات

كل النصوص الجديدة مضافة إلى القاموسين typed. الاتجاه والعناصر النشطة والسهام والحدود والمسافات تدعم RTL/LTR، والبريد يبقى LTR. Intl ينسّق التاريخ والعدد. تغيير اللغة لا يعيد تحميل هوية الإدارة؛ الاختبارات تؤكد بقاء مفتاح اللغة وحده في التخزين.

## L. الإتاحة

اختبارات Admin الموسعة شملت العربية والإنجليزية عند 320/375/768/1024/1440/1920، axe الكامل، landmarks، عدم التجاوز الأفقي، قائمة الهاتف وEscape، تركيز التفاصيل والتأكيد والعودة بعد القرار، طول سبب الرفض، والتقديم مرة واحدة. المقاسات الكبيرة والهاتف اختُبرت داخل Edge/Chromium headless. عناصر select/textarea لها مؤشرات تركيز، والإجراءات 44px، ودعم reduced motion موجود.

**حدود صريحة:** لم تُجرَ شهادة WCAG أو قراءة شاشة يدوية أو Safari/Firefox. محاولة تكبير واجهة المتصفح باختصار لوحة المفاتيح في headless لم تغير DPR أو عرض viewport؛ لذلك **تكبير browser chrome الفعلي إلى 200% مصنّف NOT TESTED**. اختبارات reflow عند العروض الصغيرة ناجحة، واختبار CSS zoom 200% القائم لصفحة الترحيب نجح؛ هذا لا يُسمّى اختبار zoom حقيقيًا لصفحة Admin. الدليل اليدوي يتضمن هذه الخطوة.

## R. مراجعة الرجوع

بقيت مصادقة كلمة المرور ومسارات Parent/Specialist والتحقق وإعادة الإرسال وربط المزودين والخصوصية والجلسة تحت التطبيق نفسه. اختبارات الوحدة والمكون وHTTP/Redis/PG والمتصفح تغطي الأساس. لا تغيير لمزودي Google/Facebook أو mail/storage adapter أو Prisma schema أو bootstrap أو سياسات الجلسة. بقي منع Parent/Specialist من Admin، ورفض Admin الموقوف، وحماية المستند على الباك.

## S. الحدود

لا إدارة مستخدمين/مسؤولين أو محتوى أو أنشطة أو audit عام أو إعدادات بلا endpoints. القائمة محدودة بـ100 والبحث محلي؛ ملخص المعلّق عالمي. لا refresh-session جديد. لا تحقق بريد مزعوم للحساب. لا قياس وصول بريد أو رفع Supabase حي أثناء المهمة. لا شهادة قارئ شاشة أو zoom متصفح حقيقي. لا حاجة لمايجريشن لهذه الميزة.

المعاينة المحلية تستخدم الباك الجديد على 3001 والواجهة على 5190. مُنع إرسال البريد في **عملية المعاينة فقط**؛ لم يتغير ملف البيئة الأصلي أو خدمة التطوير الأصلية. الاختبارات لا تفوض اتخاذ قرارات على حسابات حقيقية.

## T. دليل الاختبار اليدوي

الأوامر الكاملة في [دليل التشغيل](admin-frontend-experience.md#local-windows-walkthrough). افتح `http://127.0.0.1:5190/login` وسجل بحساب Admin مصرح. افحص العدد وروابط المراجعة، الحالات والبحث، التفاصيل والمستند الخاص، اللغات، Tab/Enter/Escape، الموبايل، وzoom المتصفح 200% يدويًا. لا توافق أو ترفض حسابًا حقيقيًا للتجربة؛ القرارات تختبر بهويات البيئة المعزولة. الخروج وتحديث الصفحة يجب أن يطلبا الدخول مجددًا.

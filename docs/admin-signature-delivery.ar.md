## 3. المعمارية والسياق

رُوجعت تعليمات AGENTS، ملفات README، `docs/architecture.md`، وثائق المصادقة والإدارة وV2، مخطط Prisma، عقود الطلبات والمراجعة والمستندات، session provider، الراوتر، الترجمة، التصميم والاختبارات. لا يوجد PRD مستقل؛ الطلب الصريح والوثائق القائمة يحددان نطاق العرض. حُفظ اسم ملف المعمارية الصغير دون إعادة تسمية.

يبقى React عميلًا لـNestJS. لا وصول مباشر إلى PostgreSQL أو Storage أو FastAPI. لم تُضف حزمة أو endpoint أو migration، ولم تتغير سياسات المصادقة أو التأهيل أو الاحتفاظ بالملفات. مكوّن `AdminApplicationDetails` يعرض البيانات ويستدعي callbacks؛ الصفحة تملك الطلبات الموثقة والقفل المتزامن للعملية. لا مزود مصادقة أو ترجمة مكرر.

## 6. القائمة الجانبية

هوية ناطق الأصلية وأيقوناته موحّدة. الحالة النشطة تجمع سطحًا مميزًا وحدًا منطقي الاتجاه ووزنًا أقوى و`aria-current`. المتنقل يفتح native dialog يجعل بقية الصفحة inert. Tab وShift+Tab يبقيان بين عناصره؛ Escape وزر الإغلاق والنقر على الخلفية واختيار وجهة يغلقونه. يرجع التركيز للزر، وتُغلق النافذة عند الانتقال لحجم الديسكتوب. لا توجد وجهات وهمية أو أقسام مستقبلية مفعّلة.

## 7. الرأس

سياق الصفحة واضح، ومبدّل اللغة بلا إطار يحيط بإطار آخر. زر اللغة النشطة بسطح واحد وأهداف لمس 44px. الخروج بأيقونة من العائلة نفسها، ويستخدم `session.signOut` القائم دون تغيير سلوكه.

## 8. النظرة العامة

العدد من endpoint الملخص المحمي الموجود في الأساس. التحميل لا يعرض صفرًا مؤقتًا؛ فشل الخدمة يعرض رسالة وإعادة محاولة. للصفر رسالة صريحة ورابط صالح لعرض الطلبات السابقة. زر المراجعة يحدد `PENDING_REVIEW`، ورابط جميع الطلبات مستقل. لا رسوم بيانية أو أرقام مستخدمين أو نشاط حديث غير مدعوم ببيانات.

## 9. طلبات الأخصائيين

اسم صاحب الطلب والبريد والتخصص والتاريخ والحالة والإجراء منظّمة في جدول ديسكتوب وصفوف مخصصة للموبايل. البحث محلي ولا يكرر طلبات API. الفلاتر تستخدم الحالات الحقيقية الأربع فقط. عدد النتائج هو طول العرض المفلتر من طول القائمة المحمّلة، وليس مجموع قاعدة البيانات.

التفاصيل تفصل المعلومات المهنية والمستند والقرار. التأكيد يذكر هوية صاحب الطلب، والرفض يتطلب السبب حسب العقد القائم 10–1000 محرف بعد trim. زر التأكيد يُعطّل أثناء التنفيذ، والقفل المرجعي يمنع عمليتين. لا تحديث تفاؤلي للحالة؛ يُعاد جلب القائمة بعد نجاح الخادم. يبقى فلتر الانتظار قائمًا، فيختفي الطلب الذي حُسم ويعود التركيز إلى عنوان القائمة إن لم يعد الصف موجودًا. عند 409 يمكن إعادة جلب التفاصيل لإظهار الحالة والسجل الحقيقيين.

## 10. الحساب الحالي

يعرض دور المسؤول مرة واحدة ثم البريد القادم من الإسقاط المعتمد. لا شارة «بريد موثّق» لأن API الحساب لا يوفّر هذا الدليل. لا UUID أو ادعاء صلاحيات أو حالة بريد مستنتجة من الدور.

## 11. الجلسة

JWT في الذاكرة كما هو. لا localStorage/sessionStorage للتوكن، ولا cookie أو refresh endpoint. إعادة تحميل الصفحة أو فتح تبويب آخر يتطلبان الدخول. رسائل الدخول وانتهاء الجلسة القائمة تشرح السياق؛ لا تحذير تقني متكرر في تذييل الإدارة. هذا يحافظ على قرار الأمان الحالي مقابل تكلفة إعادة الدخول. أي جلسة دائمة تحتاج تصميمًا وموافقة مستقلين، ولم تُنفّذ هنا.

## 12. الأصول المرئية

أصل SVG أصلي `CommunicationMotif`، خفيف ومخفي عن قارئات الشاشة، للنظرة العامة والفراغ. لا صور أطفال، ولا صور مولدة تمثل واجهة مزيفة، ولا صور خارجية أو خطوط تُحمّل من مزود خارجي. استُخدم الشعار والأيقونات الموجودة كما هي. لا حاجة لصورة raster لهذه الأشكال القابلة للرسم بالكود.

## 13. العربية والإنجليزية

النصوص الجديدة ضمن القاموسين typed القائمين. الاتجاهات والمسافات وحدود التنقّل منطقية، والبريد LTR ومعزول. الأرقام والتواريخ تستخدم Intl. الخط محلي Segoe UI مع Tahoma وArial كبدائل، دون ادعاء شراء أو تركيب خط جديد. فُحصت اللغتان في الأحجام الستة، ويُختبر تبديل لغة إشعار النجاح بعد القرار دون تكرار العملية.

## 14. إمكانية الوصول

شملت الاختبارات axe، التباين، لوحة المفاتيح، التركيز، حصره وإرجاعه في الدرج، عناوين التأكيد، الجداول، labels، إعلانات الحالة، RTL/LTR، reduced motion، وعدم التجاوز الأفقي. كشفت الجولة الأولى تباينًا غير كافٍ على السطح الأخضر؛ عُدّل النص الثانوي واختُبر مجددًا. اختُبر التكبير الحقيقي عند 200% عبر ملف متصفح معزول، وليس CSS zoom أو pinch: `devicePixelRatio=2`، وعرض داخلي 705 بدل 1410، مع CSS zoom=1 وvisualViewport.scale=1. فحص مستقل للّغتين يشمل النظرة والقائمة والتفاصيل والتأكيد.

صيغة تفضيل التكبير موثقة في [مصدر Chromium الرسمي](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/browser/ui/zoom/chrome_zoom_level_prefs.cc). لم تتغير إعدادات متصفح المستخدم. لا اختبار يدوي لقارئ شاشة، ولا Safari/Firefox؛ axe ليس شهادة WCAG كاملة.

أوامر Windows PowerShell الدقيقة في [دليل التشغيل](admin-signature-experience.md#evidence-and-local-operation). افتح `http://127.0.0.1:5190/login` على نفس الكمبيوتر، وسجّل بحساب مسؤول موجود تملك حق استخدامه. الخادم المستخدم للمعاينة `http://localhost:3001`. لا تشغّل نسختين على المنفذ نفسه.

افحص العدد والرابط، وانتقل للقائمة وجرّب البحث والحالات والتفاصيل. استخدم حسابات وPDF اصطناعية على البيئة المعزولة فقط لتجربة القرار والتنزيل. اختبر العربية والإنجليزية، Tab وShift+Tab وEscape والنقر على الخلفية، وتغيير الحجم أثناء فتح الدرج. اختبر عرض 320/375/768/1024/1440/1920 وتكبير المتصفح 200%. الخروج وإعادة التحميل يتطلبان الدخول مجددًا. لا ترسل كلمات المرور أو مفاتيح الخدمات في المحادثة.

## 24. تحسينات لاحقة مبررة

API pagination/search لتجاوز حد 100 يحتاج مهمة عقود مستقلة. فحص يدوي لقارئات الشاشة ومتصفحات أخرى مفيد قبل النشر. الجلسات الدائمة الآمنة وإضافة metadata أصلية للمستندات يحتاجان تصميمًا وموافقة مستقلين. لا تنفيذ تلقائي لهذه المقترحات.

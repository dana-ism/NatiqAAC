# الملف الشخصي وإعدادات المسؤول — التنفيذ والتحقق المعزول

اكتمل تنفيذ الملف الشخصي والإعدادات والصورة الدائمة ضمن المقترح الذي وافق عليه
المالك في 2026-11-14. التحقق يستخدم PostgreSQL وRedis معزولين ومعالجة Sharp فعلية؛
نقل ملفات Supabase بديل اصطناعي في الاختبارات. لم تُطبّق migration أو تُنشأ حاوية
على Supabase الحقيقي، ولم تُعدّل حسابات أو صور حقيقية. يلزم إعداد المالك المصرح
به قبل نشر هذا البناء أو إعادة تشغيله على قاعدته الحالية.

1. **المنفذ:** اسم محفوظ بدل البريد في الشريط، صورة افتراضية، قائمة حساب متاحة
   بلوحة المفاتيح، وصفحتا ملف شخصي وإعدادات، وتعديل اسم وصورة مع حماية التزامن.
2. **الأساس والفرع:** `b49be99` من `feature/google-auth-flow-finalization` وPR #11؛
   الفرع الجديد `feature/admin-profile-account-settings` يحافظ على سلسلة الاعتماد.
3. **الشريط السابق والجديد:** كان يعرض دور المسؤول وبريده؛ الآن يعرض اسم العرض
   المحفوظ وصورته الخاصة أو صورة افتراضية دائرية. البريد والدور داخل القائمة وصفحات الحساب فقط.
4. **مصدر الاسم:** `User.fullName` عبر GET `/admin/profile`، مع بديل محايد مترجم
   للاسم الفارغ أو الشبيه بالبريد؛ لا اسم مفترض ولا اعتماد على localStorage.
5. **القائمة:** فتح بالنقر أو الأسهم، وتنقل بالأسهم وHome/End، وإغلاق بـEscape
   والنقر الخارجي وTab والانتقال، مع إعادة التركيز بعد Escape. تسجيل الخروج من
   الآلية الموجودة، واللغة من نظام الترجمة الحالي.
6. **الملف الشخصي:** عرض بيانات فعلية وتعديل الاسم وحفظ وإلغاء، والتحقق من الإدخال
   وحالات التحميل والخطأ والنجاح بعد حفظ الخادم. تحديث الاسم يصل للشريط والقائمة.
7. **الصورة والتخزين:** اختيار ومعاينة وتأكيد وإلغاء واستبدال وإزالة، مع زر كاميرا
   مترجم. الخادم يفك JPEG/PNG/WebP حتى 2 MiB و4096 بكسل للضلع، ويرفض SVG والمحتوى
   الفاسد أو المتحرك، ويُنتج WebP ثابتًا حتى 512 بكسل مع إزالة metadata. الحاوية
   الخاصة المستقلة `admin-profile-avatars` تستخدم بيانات الخادم السرية فقط.
8. **الاستمرارية:** الاسم محفوظ في PostgreSQL؛ أثبت اختبار HTTP على قاعدة معزولة
   ظهوره عند قراءة موثقة جديدة، وبقاء اسم مسؤول آخر كما هو. مرجع الصورة في قاعدة
   البيانات، والملف الخاص في التخزين. اختبار المتصفح المحكوم يتحقق من العرض بعد
   إعادة الدخول. تحديث الصفحة ينهي الجلسة المؤقتة كما
   كان سابقًا؛ بعد الدخول مجددًا يُقرأ الاسم المحفوظ، دون حفظ JWT في المتصفح.
9. **الإعدادات:** معلومات الحساب، ولغة العرض المحفوظة في هذا المتصفح، وحالة طرق
   الدخول الحالية. إعدادات الحساب الشخصي منفصلة عن إعدادات المنصة المستقبلية.
10. **الأمان:** عرض وجود كلمة مرور محلية وحالة Google/Facebook من الهويات المسجلة،
    ورابط يعمل للمسار الموجود للربط الصريح. إثبات حديث وصلاحيات الخادم تظل مطلوبة.
11. **غير المتاح:** تغيير البريد وكلمة المرور، وفصل مزوّد، وإدارة مسؤولين آخرين،
    لا إعدادات وهمية أو نظام جلسات جديد. تشغيل الصور في بيئة المالك ينتظر الإعداد المصرح به.
12. **API:** GET `/admin/profile` وPOST `/admin/profile/name` جديدان. بقي `/auth/me`
    و`/admin/overview` وOAuth وقرارات الأخصائيين دون تغيير لعقودها. أضيف رفع الصورة
    واسترجاعها وإزالتها تحت `/admin/profile/avatar`، و`hasAvatar` في إسقاط الملف.
13. **قاعدة البيانات والتخزين:** حقل `User.avatarKey` اختياري عبر migration
    `20261114000100_admin_avatar`، دون backfill. طُبّق بـPrisma Migrate على قاعدة
    الاختبار المعزولة فقط. أُعيد توليد Prisma Client بالأمر المعتمد، وأضيف Sharp
    0.35.5، وأضيف إعداد مثال `ADMIN_AVATAR_BUCKET` دون تعديل ملف بيئة المالك.
14. **الصلاحيات:** JWT والدور الحالي من قاعدة البيانات، والمسؤول النشط فقط. لا
    معرّف مالك في DTO، ولا تعديل بريد أو دور أو حالة، ولا رفع صلاحيات. لا عمليات
    حذف/تعليق مسؤول؛ الحماية القائمة وتهيئة المسؤول الأول لم تتغير.
15. **العربية والإنجليزية:** رسائل typed ضمن نظام الترجمة الحالي، وRTL/LTR، وعناوين
    وروابط وقيم مترجمة، والبريد داخل bdi. اسم المستخدم نفسه لا يُترجم.
16. **الاستجابة والإتاحة:** الاختبارات تستهدف 320 و375 و768 و1024 و1440 و1920،
    وzoom حقيقي 200%، وaxe، والتركيز ولوحة المفاتيح وحدود القائمة. النتائج أدناه.
17. **الصور:** [المعرض](assets/admin-profile/README.md) من Edge وAPI اصطناعي؛ لا
    صور حسابات حقيقية ولا ادعاء اختبار Storage حي. يشمل المعاينة والصورة المحفوظة
    وتأكيد الإزالة إضافة إلى الملف والقائمة والإعدادات والمقاسات والتكبير.
18. **الملفات:** AdminProfileController/Service/module، واختبارات HTTP والتكامل؛
    AdminLayout وAdminAccountMenu وAdminProfilePage وAdminAccountSettingsPage وCSS
    وprofile context/API/messages، ومسارات App والترجمات، واختبارات fixtures/Admin
    والمتصفح، والتوثيق. ويشمل AvatarStorageService وPrivateBucketStorage المشترك
    وAdminPhotoEditor وSchema/migration والملفات المولدة وملفات npm. قائمة Git/PR
    هي المرجع الدقيق؛ واجهة Flutter وخدمة FastAPI لم تتغيرا.
19. **الفحوص:** تُسجل أدناه أوامر ونتائج المرحلة، مع تمييز قاعدة حقيقية معزولة عن
    API المتصفح المحكوم. لا تكفي صور أو mocks وحدها لإثبات حفظ فعلي.
20. **المتبقي:** [خطوات إعداد المالك التي تحتاج موافقة تشغيل منفصلة](admin-profile-account-settings.md#owner-setup-requiring-separate-approval):
    تطبيق migration على الهدف الحقيقي بعد فحص التاريخ، وإنشاء حاوية خاصة بقيود
    2097152 بايت وMIME `image/webp` دون صلاحيات وصول مباشر للعميل، وضبط متغير الخادم،
    ثم نشر النسختين وتجربة مخولة. لا ادعاء لنجاح Storage أو Google حي هنا.
    تعطل Storage أو توقف العملية بين الحفظ والتنظيف قد يترك ملفًا يتطلب تسوية
    منفصلة؛ يُسجل تحذير مشغل منقح، ولا توجد عملية purge واسعة أو حذف لوثائق الأخصائيين.
21. **التحقق اليدوي:** بعد تشغيل Backend والواجهة المتوافقين، سجّل الدخول كمسؤول؛
    افتح قائمة الاسم؛ جرّب Escape والأسهم والنقر الخارجي؛ عدّل الاسم ثم أعد الدخول؛
    تحقق من ظهوره، ومن معلومات الحساب وبدائل كلمة المرور/البريد غير المتاحة؛
    جرّب اللغة والربط الموجود وتسجيل الخروج. بعد الإعداد، جرّب الصورة والإلغاء
    والاستبدال والإزالة وإعادة الدخول بحساب اختبار مخوّل. لا تستخدم حسابًا حقيقيًا كعينة آلية.
22. **Git والتسليم:** الفرع `feature/admin-profile-account-settings`، وحُفظ التنفيذ
    الأول في `41d5b08ee9e14a69e72d66b7e0ebbe5640b39b94`، واستكمال الصور في
    `aded829b7cb7ab6728be5551f87dabbde0f2a3c8`، ودُفعا إلى origin.
    [PR #12](https://github.com/dana-ism/NatiqAAC/pull/12) مفتوح وجاهز للمراجعة،
    بعنوان “Add Admin profile, private avatars and personal account settings”،
    على فرع Google عند `b49be99`، ويعرض [قائمة الملفات](https://github.com/dana-ism/NatiqAAC/pull/12/files).
    يتبعه commit توثيق نتائج التسليم؛ رأس الفرع النهائي ظاهر في PR. لم يُعدّل main،
    ولم يحدث merge أو force-push، وauto-merge غير مفعّل.

## نتائج المرحلة

- Backend unit: 428 اختبارًا ناجحًا.
- HTTP: 69 اختبارًا ناجحًا، منها 20 لعقد الملف الذاتي.
- PostgreSQL/Redis المعزولان: 46 اختبار تكامل ناجحًا، منها 10 للملف/الصورة وحفظ
  الاسم والتزامن والعزل بين مسؤولين وتنظيف الرفع الفاشل وحدود HTTP وإلغاء الوصول،
  وتجربة SQL الإضافي نفسه على جدول مؤقت يحوي سجلات اصطناعية قديمة؛ بقيت قيمها
  كما هي وأصبح الحقل الجديد NULL، دون تغيير بيانات الجدول العام.
- Redis: 21 اختبارًا ناجحًا.
- Web: 147 اختبارًا ناجحًا.
- المتصفح Edge: 138 اختبارًا ناجحًا في الجولة الشاملة، بينها 24 للملف والصور؛
  أثبتت فتح منتقي الملفات والمعاينة والحفظ والاسترجاع والاستبدال والإزالة والعودة
  بعد الدخول وفشل القراءة وإعادة المحاولة والتعارض دون نجاح وهمي. شملت اللغتين
  والمقاسات الستة والتكبير الحقيقي 200% وaxe ولوحة المفاتيح. لم تُشغّل حالتان
  اختياريتان تتطلبان opt-in لاختبار API حقيقي. نقل المتصفح اصطناعي؛ ليس اختبار
  Storage حيًا. المعرض يحوي 42 صورة، وأُعيدت معارض المراحل السابقة من النسخ
  المحفوظة بعد الجولة دون إدخال تغييراتها الناتجة عن إعادة التصوير في التسليم.
- البناء وTypeScript وLint للخادم والواجهة ناجحة. فحص تنسيق web الكامل يفشل في
  18 ملفًا غير معدل بسبب CRLF فقط؛ أكد فحص مستقل مطابقتها لـHEAD بعد التطبيع.
  اجتازت الملفات المعدلة فحص Prettier و`git diff --check`؛ لم تُعدّل ملفات قديمة
  لمجرد إصلاح ذلك الفحص العام. فحص القيم الحساسة لم يجد تطابقًا في ملفات التسليم.

فحص npm audit قارن lockfile الأساسي والحالي: 26 تنبيهًا في كليهما (6 منخفضة،
18 متوسطة، 2 مرتفعة) مع نفس أسماء الحزم المتأثرة، ولا تنبيه لـSharp أو اسم متأثر
جديد. لم يُنفّذ `audit fix` أو upgrade غير مرتبط بالمهمة.

أوامر التحقق: `npm.cmd test -- --runInBand` و`npm.cmd run test:http -- --runInBand`
و`npm.cmd run test:e2e -- --runInBand` و`npm.cmd run test:redis -- --runInBand` للخادم،
مع إعدادات TEST_DATABASE_URL/TEST_REDIS_URL المحلية بعد التحقق من وسم حاويات الاختبار.
للواجهة: `npm.cmd test -- --reporter=dot --maxWorkers=1` و`npm.cmd run test:browser`
على منفذ loopback منفصل وAPI اصطناعي، إضافة إلى typecheck وlint وbuild.
فشل تشغيل Vitest أولي بمهلات عمال خلال فجوة كبيرة في توقيت الجهاز؛ نجحت إعادة
تشغيل الاختبارات الـ147 بعامل واحد دون توسيع مهلات الاختبار.

كشف اختبار التكامل نقص استيراد PrismaModule وعولج قبل نجاح المجموعات الكاملة.
وكشفت اختبارات المتصفح تجاوز عرض الشريط عند 320px وعولج؛ نجحت إعادة الفحص
بالعربية والإنجليزية. جميع بيانات واختبارات الصور اصطناعية؛ الوصول الحقيقي إلى
Storage لا يزال ضمن خطوات إعداد المالك المصرح بها منفصلًا.

رفضت مراجعة الموافقة الآلية محاولة إعادة تشغيل Backend المحلي بعبارة
«blocked by policy» دون تفصيل. لم يُوقف الخادم ولم تُكرر محاولة تجاوزه. الفحص
للقراءة فقط يثبت أن `/admin/profile` على 3000 لا يزال 404 رغم نجاح التطبيق الجديد
في الاختبارات المعزولة. يجب على المالك إعادة تشغيل Backend بالنسخة الحالية قبل
النشر؛ يجب تطبيق migration المصرح بها أولًا ثم إعداد الحاوية قبل تشغيل هذا البناء.
بعدها المتوقع دون تسجيل دخول هو 401.

الموافقة المحدودة وصلت في 2026-11-14، وتشمل التنفيذ والاختبار المعزول فقط.
لا موافقة معلقة لتنفيذ الكود؛ الموافقة التشغيلية على Supabase الحقيقي والحاوية
لم تُطلب أو تُفترض. لم يُعدّل مستخدم أو صورة حقيقية، ولا `opencode.json` أو `.env`.
